# Implementation Plan: Survey Management

## Overview

Replace the static JSON-driven questionnaire system with a fully dynamic, database-driven survey platform. This covers database migrations, backend models/controllers/policies/middleware, and React/Inertia frontend pages and components.

## Tasks

- [x] 1. Database migrations and schema setup
  - Create migration to drop old tables: `survey_answers`, `survey_submissions`, `survey_categories`
  - Create migration to add `year_graduated` (integer, nullable) to `users` table
  - Create migration for `surveys` table (id, title, description, status enum, timestamps, soft deletes)
  - Create migration for `sections` table (id, survey_id FK, title, display_order, timestamps; unique on survey_id+title)
  - Create migration for `questions` table (id, section_id FK, question_identifier, label, type enum, options JSON, display_order, is_required, timestamps; unique on section_id+label)
  - Create migration for `responses` table (id, survey_id FK, user_id FK, question_id FK, answer_value text, submitted_at, timestamps; indexes on survey_id+user_id and question_id)
  - Create migration for `survey_drafts` table (id, user_id FK, survey_id FK, answers JSON, last_section_id FK, updated_at; unique on user_id+survey_id)

## Notes

- Tasks marked with `*` are optional and can be skipped for a faster MVP
- Each task references specific requirements for traceability
- Property tests use `eris/eris` (PHP) with tag format: `// Feature: survey-management, Property {N}: {property_text}`; minimum 100 iterations per property test
- `SurveyCard` has no analytics link — analytics is accessed via the coordinator sidebar
- Analytics year filter covers graduation years 2018–2022 plus "All Years"
- Draft saving is server-side on every "Next" click; "Back" is client-side only
